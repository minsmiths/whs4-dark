# 보안 위협 및 대응

CLAUDE.md §4.2에서 참조하는 상세 위협표입니다.

| 위협 | 시나리오 | 대응 |
| --- | --- | --- |
| 악성 스크립트 / 브라우저 익스플로잇 | 렌더링한 페이지에 심어진 악성 JS가 Chromium 취약점을 이용해 렌더링 프로세스를 장악하려 시도 | 격리된 일회성 컨테이너에서만 실행, Chromium 샌드박스 유지(`--no-sandbox` 금지), 컨테이너 안에 자격증명 없음(뚫려도 훔칠 게 없음), 의심 시 컨테이너 폐기 후 재생성 |
| 유출파일·첨부파일을 통한 멀웨어 | "샘플 데이터"로 위장한 실행파일·압축파일 다운로드 유도 | 파일 자동 다운로드 금지, 존재 여부만 기록 |
| 세션 파일(쿠키) 탈취 | `sessions/` 폴더의 로그인 세션이 유출되면 계정 탈취로 이어짐 | named volume에만 보관, 호스트로 자동 반출 안 함 — 컨테이너 밖으로 반출되는 건 결과 MD 파일 하나뿐 |
| Tor 회선 신뢰성(악성 exit node) | 클리어넷 미러 접속 시 exit node가 응답을 조작할 가능성 | `.onion` 네이티브 주소 우선 사용(exit node를 거치지 않음), 클리어넷 접속 시 HTTPS 여부 확인 |
| 실제 IP·신원 노출(OPSEC) | Tor 우회 트래픽, DNS 유출, 브라우저 fingerprint로 조사자 신원이 대상 사이트 운영자에게 노출 | 로그인 포함 모든 접속을 컨테이너 안 Tor 프록시로만 수행, Tor SOCKS 포트는 로컬호스트에만 바인딩. 환경 중립화(locale/timezone 등)는 확장 단계 |
| 사이트 운영자의 자동화 탐지·역공격 | 정각 고정 간격 요청 패턴으로 크롤러임이 식별돼 차단되거나 허위 데이터를 공급받음(Source Poisoning) | 요청 간 랜덤 지연, 수집 결과는 항상 "관찰"로만 기록하고 자동 확정하지 않음 — 오염된 데이터가 들어와도 사람 검토 전엔 확정되지 않음 |
| 로그·파일명 인젝션 | 수집한 텍스트(사이트명·게시글 제목 등)에 특수 문자열이 섞여 로그나 파일 경로에 그대로 쓰이는 경우 | 로그 기록 시 제어문자·개행 제거, 파일명은 화이트리스트 문자만 사용 |
| (확장 단계) AI 요약에 대한 프롬프트 인젝션 | 페이지 안에 "이전 지시를 무시하고..." 같은 문구를 심어 향후 AI 요약 단계를 조작 시도 | MVP는 AI 요약 자체를 쓰지 않음 — 확장 단계에서 AI 요약 도입 시 원문 대신 구조화된 사실만 입력하는 방식으로 대응 |

**방어 범위 밖으로 명시하는 것**: 국가 수준 공격자의 0-day를 이용한 컨테이너·호스트 탈출,
Docker·Chromium 자체의 알려지지 않은 취약점, 물리적 접근을 통한 공격. 개인·소규모 프로젝트 규모로
이 세 가지를 막는 건 현실적으로 불가능하고, 시도하면 실제로 자주 마주칠 위협(위 표)에 써야 할
자원을 낭비하게 된다. 대신 "뚫려도 피해가 크지 않게"(자격증명 없음, 일회성 컨테이너, 결과물은
MD 파일 하나만 반출) 원칙으로 피해를 한정하는 데 집중한다.
