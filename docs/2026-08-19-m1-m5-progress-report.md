# 다크웹 크롤러 MVP — M1~M5 개발 진행 보고서 (2026-08-19)

> 이 문서는 개발 과정을 잘 모르는 분도 읽을 수 있도록 쉽게 정리한 진행 보고서입니다.
> 기술적으로 더 자세한 규칙은 [CLAUDE.md](../CLAUDE.md), 로드맵 원본은

## 한 줄 요약

로드맵 M1(세션 매니저)부터 M5(리포트 생성 + 전체 통합)까지 구현을 마쳤고, 실제 테스트 50개를
전부 통과시켰습니다. 추가로 "사람이 직접 로그인할 방법(VNC)"이 빠져 있던 걸 발견해서 채워
넣었고, Docker 이미지도 실제로 빌드해서 정상 동작을 확인했습니다. 다크웹 사이트를 이용한
검증은 자동화 규칙(§3-8)에 따라 하지 않았습니다.

## 1. 시작할 때 상태는 어땠나

작업을 시작하기 전, 이 프로젝트는 "뼈대"만 있는 상태였습니다. 파일은 다 있지만 일부 로직이
`TODO` 주석으로 남아 있었고, 실제로 대상 사이트에 접속해서 정보를 모으는 부분(`investigate.py`의
핵심 실행 흐름)은 아예 막혀 있었습니다("M2에서 구현 예정" 이라는 메시지만 뜨고 종료).

확인해보니 예상보다는 이미 많이 되어 있었습니다 — 세션 저장/불러오기, 리포트 생성 규칙,
일부 수집 로직은 이미 짜여 있었고, 정말 비어 있던 부분은 아래와 같았습니다.

- 규칙/가입 페이지 원문을 실제로 가져오는 부분
- 게시글 수/통계를 추정하는 부분
- 게시글 언어를 감지하는 부분
- 개인정보(이메일/전화번호) 존재 여부를 기록하는 부분
- 전체 파이프라인을 실제 브라우저(Tor 경유)로 연결하는 부분
- 최종 결과 문서(23개 항목)를 빠짐없이 채우는 부분

## 2. 마일스톤별로 무엇을 했나

### M1 — 로그인 세션 저장/재사용

**하는 일**: 다크웹 사이트 중 로그인이 필요한 곳은, 크롤러가 자동으로 로그인하지 않습니다
(자동 로그인은 규칙상 금지). 대신 사람이 한 번 로그인하면 그 "로그인된 상태"(세션)를 파일로
저장해뒀다가, 다음부터는 그 파일을 재사용합니다.

**한 일**: 이 부분 코드는 이미 다 짜여 있어서, 실제로 잘 동작하는지 확인하는 테스트만 새로
작성했습니다.

- 세션 파일을 저장했다가 다시 불러오면 정상적으로 "로그인된 상태"로 인식되는지
- 세션 파일이 없거나 삭제됐을 때, 크롤러가 알아서 다시 로그인을 시도하지 않고 "세션 만료"만
  기록한 뒤 죽지 않고 다음 작업을 계속하는지

**나중에 추가로 발견한 문제**: 정작 사람이 "로그인 화면을 볼 방법"(VNC)이 컨테이너에 빠져
있었습니다. 이건 4번 항목에서 별도로 설명합니다.

### M2 — 사이트가 살아있는지 확인 + 사이트 구조 파악

**하는 일**: 사이트가 정상 작동 중인지, 압류/폐쇄된 건 아닌지 확인하고, 사이트의 메뉴 구조와
가입 규칙을 읽어옵니다.

**한 일**:
- "규칙/FAQ 페이지 원문을 그대로 가져와서 인용하는" 기능을 완성했습니다 (요약하지 않고
  원문 그대로 — AI가 임의로 요약하면 안 되는 규칙 때문입니다).
- 페이지를 열람할 때마다 원본 HTML을 별도 폴더에 저장하는 기능(`snapshot.py`)을 새로 만들었습니다.
  이건 나중에 "크롤러가 뭘 봤는지" 사람이 검증할 수 있게 하는 안전장치입니다.

### M3 — 통계 + 게시글 표본 수집

**하는 일**: 사이트 규모(게시글 수 등)를 추정하고, 게시글 일부를 표본으로 가져와서 어떤
언어를 쓰는지, 한국 관련 유출로 의심되는 게시글이 있는지 확인합니다.

**한 일**:
- 회원수/게시글수가 화면에 직접 안 보일 때, 페이지 번호(예: "42페이지까지 있음")를 보고
  대략적인 규모를 추정하는 로직을 완성했습니다.
- 게시글 제목의 언어를 자동으로 감지하는 기능을 완성했습니다.
- **개인정보 보호 규칙**에 따라, 이메일/전화번호처럼 보이는 패턴이 있으면 "있다/없다"와
  "어떤 종류인지"만 기록하고, 실제 이메일 주소나 전화번호 자체는 절대 저장하지 않도록
  만들었습니다.

### M4 — 다른 사이트 언급 찾기 + 가입 조건 확인 + 활동 유저 집계

**하는 일**: 게시글 안에서 다른 사이트 주소나 텔레그램 채널이 언급되면 "발견했다"고만 기록하고
(자동으로 "이 사이트랑 연결된 곳"이라고 단정하지 않음), 가입 화면에 어떤 정보를 입력해야
하는지 확인하되 실제로 가입 시도는 하지 않습니다.

**한 일**: 대부분 이미 구현돼 있어서, "가입 화면에 진짜로 아무것도 제출하지 않는지"를 실제
네트워크 요청 로그로 검증하는 테스트를 추가했습니다(요청이 0건이어야 통과).

**발견해서 고친 버그**: 원래 코드는 "규칙 페이지에서 읽은 가입 조건"과 "가입 화면에서 읽은
입력 항목"이 같은 이름의 칸에 저장되고 있었는데, 이러면 나중에 실행된 쪽이 먼저 쓴 내용을
덮어써버립니다. 두 정보를 다 남기도록 수정했습니다.

### M5 — 최종 결과 문서 만들기 + 전체 연결

**하는 일**: 지금까지 모은 정보를 모아서 사람이 검토할 수 있는 마크다운(.md) 보고서 파일로
만듭니다. 노션에 옮겨 적을 23개 항목이 하나도 빠짐없이 채워져야 합니다.

**한 일**:
- 사용자님이 알려주신 23개 항목의 정확한 명세(어떤 항목이 자동으로 채워도 되고, 어떤 항목은
  사람만 채워야 하는지)를 그대로 코드에 반영했습니다.
- "사람만 채워야 하는 항목"(예: 담당자, 국가, 게시 여부)은 크롤러가 아무리 그럴듯한 값을
  보내도 항상 빈칸으로 남도록 다시 한번 강제했습니다.
- "들어가는 법"(가입 조건) 항목은 노션에는 올리지 않고 내부 참고용으로만 남겨야 하는
  항목이라, 별도 섹션으로 분리했습니다.
- 실제 브라우저(Tor 프록시 경유)를 띄우고, 세션을 불러오고, 7단계를 순서대로 실행하고,
  결과 파일을 저장하는 전체 흐름을 연결했습니다.
- **발견해서 고친 버그**: 화이트리스트(승인된 사이트 목록) 파일 경로를 실행 중에 바꿔도
  반영이 안 되는 문제가 있었습니다(프로그램이 처음 켜질 때 값을 고정해버림). 실행할 때마다
  최신 경로를 다시 읽도록 고쳤습니다.

## 3. VNC(사람이 화면 보고 로그인하는 기능)

다크웹 사이트에 로그인하거나 "나는 로봇이 아닙니다" 같은 사람 확인을 통과하려면, 그 순간만큼은
사람이 직접 화면을 보고 클릭/입력을 해줘야 합니다(크롤러가 자동으로 하면 안 되는 부분입니다).

문제는 이 크롤러의 브라우저가 격리된 Docker 컨테이너 안에서 뜬다는 점입니다. 컨테이너 밖
(진짜 내 컴퓨터)에서 그 다크웹 사이트를 직접 열어서 로그인해버리면, "크롤러는 격리된 공간
안에서만 실행한다"는 안전 원칙이 깨집니다. 그래서 컨테이너 밖으로 사이트 화면을 꺼내오는 대신,
컨테이너 **안**에서 뜬 브라우저 화면을 원격으로 "들여다볼 수만" 있게 해주는 기술이 필요한데
그게 VNC입니다 — 화면 공유 프로그램이라고 생각하시면 됩니다.

추가한 내용은 아래와 같습니다.

- `Dockerfile`에 화면 없이도 브라우저를 띄울 수 있는 가상 화면 프로그램(Xvfb)과 그 화면을
  원격으로 볼 수 있게 하는 프로그램(x11vnc)을 설치했습니다.
- 평소 자동 크롤링은 화면이 필요 없는 방식(headless)이라 이 프로그램들이 켜지지 않고,
  "사람이 로그인해야 할 때"만 별도 명령(`docker/login.sh`)으로 켜지도록 분리했습니다.
- 로그인 전용 스크립트(`login_session.py`)를 새로 만들었습니다: 브라우저를 화면이 보이는
  방식으로 띄우고, 사람이 로그인을 마치면 Enter 키를 눌러 그 로그인 상태를 저장합니다.
- VNC 접속 비밀번호는 이미지 안에 하드코딩하지 않고, 실행할 때 매번 지정하도록 만들었습니다.

## 4. 검증한 것들

### 자동 테스트

- **테스트 50개 전부 통과**. 실제 다크웹 사이트에는 한 번도 접속하지 않고, 가짜 샘플
  HTML 파일(`tests/fixtures/` 폴더, 실제 사이트를 흉내만 낸 것)로만 검증했습니다.
- 코드 스타일 검사(ruff)도 전부 통과했습니다.

**어떤 걸 테스트했는지 예시 몇 가지**

| 확인한 것 | 어떻게 확인했나 |
| --- | --- |
| 세션 파일을 지우고 다시 실행해도 프로그램이 죽지 않는다 | 세션 파일을 일부러 삭제한 뒤 실행 → "세션 만료" 기록만 남기고 나머지 6단계를 끝까지 진행하는지 확인 |
| 가입 화면에 절대 실제로 제출(가입 시도)하지 않는다 | 가짜 가입 페이지를 열어 정보만 읽어오게 한 뒤, 그동안 발생한 네트워크 요청을 전부 기록해서 POST 요청이 0건인지 확인 |
| "담당자", "국가" 같은 사람 전용 칸은 크롤러가 절대 못 채운다 | 크롤러가 그럴듯한 가짜 값("확정됨(자동)" 등)을 일부러 넣어봐도, 최종 문서에는 항상 "안 봄"으로만 나오는지 확인 |
| 이메일/전화번호는 원문이 절대 저장되지 않는다 | 가짜 이메일이 적힌 게시글 제목으로 테스트 → 결과에는 "이메일 발견됨"만 남고 실제 이메일 주소 문자열은 어디에도 없는지 확인 |
| 규칙 페이지 원문을 요약하지 않고 그대로 가져온다 | 가짜 규칙 페이지("가입은 초대 코드가 필요합니다" 등)를 읽게 한 뒤, 그 문장이 결과 문서에 그대로(줄여지지 않고) 들어있는지 확인 |
| 승인 안 된 URL은 바로 거부한다 | 화이트리스트에 없는 URL로 실행해보고 즉시 에러로 끝나는지 확인 |
| 브라우저가 보안 기능을 끈 채로 실행되지 않는다 | 브라우저를 실제로 띄워보고 실행 옵션에 `--no-sandbox` 같은 위험한 옵션이 없는지 확인 |

### 보안 규칙 자동 검사 (CI가 매번 자동으로 확인하는 항목)

- 브라우저 보안 기능을 끄는 옵션(`--no-sandbox` 등)이 코드 어디에도 없음 — 통과
- 결과 파일(`output/` 폴더) 말고 다른 경로로 정보를 외부에 보내는 코드가 없음 — 통과
- 유출 파일을 실제로 다운로드하는 코드가 없음 — 통과

### Docker로 실제 빌드/실행 검증 (다크웹 사이트 미접속)

- `docker build`로 이미지가 실제로 만들어지는지 확인 — 성공
- 컨테이너 안에서 모든 코드 파일이 문법 오류 없이 정상적으로 불러와지는지 확인 — 성공
- Tor가 컨테이너 안에서 정상적으로 켜지는지 확인 — 성공 (`tor is running.`)
- VNC용 프로그램(Xvfb, x11vnc)이 잘 설치됐는지 확인 — 성공
- 컨테이너 안에 노션/깃허브 같은 외부 서비스 비밀번호(자격증명)가 하나도 없는지 확인 —
  0건, 통과
- 브라우저(Chromium)가 보안 기능을 끄지 않은 채로 정상적으로 실행되는지 확인 — 성공
  (실제 사이트 대신 테스트용 HTML로만 확인)

### 아직 검증하지 못한 것 (사람이 직접 해야 하는 부분)

- VNC로 실제 사람이 화면을 보면서 로그인하는 흐름 자체 (스크립트 배선까지는 확인했지만,
  실제 VNC 뷰어로 접속해서 로그인해보는 건 아직 안 해봤습니다)
- 실제 승인된 다크웹 대상 1곳으로 전체 파이프라인을 돌려보는 것 (로드맵 M6에 해당,
  규칙상 AI가 직접 하면 안 되는 부분이라 처음부터 이번 작업 범위에서 제외했습니다)
- 대상 사이트의 실제 화면 구조(선택자)에 맞춰 일부 수집 로직을 미세 조정하는 것
  (실제 사이트 화면을 봐야만 확정할 수 있는 부분)

## 5. 다음에 할 일 제안

1. 담당자가 실제 대상 URL을 `whitelist.yaml`에 등록
2. 로그인이 필요하면 `docker/login.sh`로 VNC 접속해서 직접 로그인 → 세션 저장
3. 실제 대상 사이트 화면을 보고 `collectors/*.py`의 선택자(TODO 표시된 부분)를 확정
4. 담당자 입회 하에 전체 파이프라인 1회 실행 (로드맵 M6)
5. [security-checklist.md](security-checklist.md)의 사람이 직접 확인해야 하는 나머지 항목 점검
