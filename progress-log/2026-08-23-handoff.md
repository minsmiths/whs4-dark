The human ran the new site-wide crawl against darkforums for real. Two real bugs surfaced from

1. **`상태`/`어니언 주소` came back "못 봄"/"안 봄" even though the page clearly loaded** (later

## Hard constraint — read this before touching anything target-related

CLAUDE.md §3-8: **the AI must never itself connect to, log into, or navigate the
real target site.** Every selector-discovery step in this project so far worked like
this instead:
1. The human runs a crawl/login via the PowerShell scripts below, which *does*
   contact the real target (that's the human's job, not Claude's).
2. `snapshot.py` saves raw HTML into a Docker named volume (`darkweb-snapshots`)
   inside the container — never auto-exported.
3. The human extracts it to a local folder with `docker cp`/volume-mount (see below),
   which they then let Claude read/grep like any other local file.
4. Claude derives selectors from that already-captured HTML and writes them into
   `site_profiles.py`. Claude does not fetch the live site itself. The one exception:
   fetching public open-source project pages (e.g. MyBB's own GitHub) is fine, since
   that's not "the target." Public real-world forums *other than the approved
   target* are also off-limits to fetch for reconnaissance purposes.

If you're an AI reading this and the human asks you to "just check the site" or "run
the crawl," redirect them to run it themselves and offer to analyze what comes back.

## Known traps worth not re-discovering

- **`.gitignore` inline comments don't work.** Git only treats a `#` as a comment
  when it's the very first character of the line. A pattern like
  `whitelist.yaml   # some comment` is parsed as one literal (non-matching) pattern
  string, not `whitelist.yaml` with a trailing comment. This exact bug existed in
  this repo's `.gitignore` for the `whitelist.yaml` rule — it never actually
  ignored the file (confirmed via `git log --all --full-history -- whitelist.yaml`,
  never committed/pushed, but it was a live landmine). Fixed 2026-08-23: comments
  now go on their own line above the pattern. If you add new ignore rules, keep
  comments on separate lines.
- **Windows Docker Desktop + host port 5900**: if a VNC *server* (not just viewer)
  ends up installed and running as a Windows service on the host (this happened once
  via a `winget install` that pulled in TightVNC's server component alongside the
  viewer), it silently binds `0.0.0.0:5900` and blocks Docker's port mapping with a
  cryptic "access forbidden" error — and is itself a minor security exposure (an
  unintended VNC server listening on all interfaces). `vnc-login.ps1` sidesteps the
  conflict by always asking Docker for a random free host port rather than assuming
  5900 is available.
- **`PowerShell` background job + multi-line backtick commands** are fragile to
  copy-paste (trailing whitespace after a backtick silently breaks continuation,
  producing confusing downstream errors like `docker: invalid reference format`).
  Both `.ps1` scripts avoid this by building the whole `docker run` invocation as one
  string internally.
- **Tor takes longer than 3 seconds to bootstrap.** The original `Dockerfile` CMD did
  `service tor start && sleep 3 && python investigate.py ...`; the first crawl in a
  fresh container would frequently time out because Tor's SOCKS proxy wasn't actually
  routing yet. Fixed via `docker/wait-for-tor.sh` (polls up to 60s).
- **`.onion` navigation is slow and sometimes just fails.** `login_session.py` no
  longer crashes on a `page.goto()` timeout — it logs a warning and still lets the
  human retry manually inside the VNC session, then proceeds to the save-session
  step regardless.
