## Hard constraint — read this before touching anything target-related

CLAUDE.md §3-8: **the AI must never itself connect to, log into, or navigate the
real target site.** Every selector-discovery step in this project so far worked like
this instead:
1. The human runs a crawl/login via the PowerShell scripts below, which *does*
   contact the real target (that's the human's job, not Claude's).
2. `snapshot.py` saves raw HTML into a Docker named volume (`darkweb-snapshots`)
   inside the container — never auto-exported.
3. The human extracts it to a local folder with `docker cp`/volume-mount (see below),
   which they then let Claude read/grep like any other local file.
4. Claude derives selectors from that already-captured HTML and writes them into
   `site_profiles.py`. Claude does not fetch the live site itself. The one exception:
   fetching public open-source project pages (e.g. MyBB's own GitHub) is fine, since
   that's not "the target." Public real-world forums *other than the approved
   target* are also off-limits to fetch for reconnaissance purposes.

If you're an AI reading this and the human asks you to "just check the site" or "run
the crawl," redirect them to run it themselves and offer to analyze what comes back.

## New files beyond the original scaffold

| File | What it does |
| --- | --- |
| `snapshot.py` | Saves raw HTML (`page.content()`) into `snapshots/<source_id>/<timestamp>/`. Called by `structure.py` (rules page) and `investigate.py` (home page, sample-list page). |
| `site_profiles.py` | Per-target selector overrides, keyed by a `platform` string set in `whitelist.yaml`. Falls back to each collector's generic guessed selector when no profile/platform is set. **This is the main lever for fixing "collector didn't collect anything real" problems** — see below. |
| `login_session.py` | Human-in-the-loop VNC login entry point. Headed Chromium, Tor proxy, `input()`-gated `session_manager.save_session()`. Doesn't crash on page-load timeout anymore (catches it, lets the human retry inside the VNC session, then still saves whatever session state exists). |
| `docker/login.sh` | Container entrypoint for the login flow: starts Xvfb + x11vnc (password via `VNC_PASSWORD` env, never baked into the image), waits for real Tor bootstrap (`wait-for-tor.sh`), runs `login_session.py`. Separate from the default `CMD` (which stays headless, no VNC overhead for normal automated crawls). |
| `docker/wait-for-tor.sh` | Polls `check.torproject.org` through the SOCKS proxy until it actually responds (up to 60s), instead of a blind `sleep 3`. Fixed a real bug where the first crawl after container start would time out because Tor wasn't bootstrapped yet. |
| `docker/vnc-login.ps1` | **Host-side** (Windows) convenience script. Picks a random free host port for VNC (avoids clashing with anything else already on 5900), generates a random VNC password each run (not reused, not pasted into chat), launches the container in a new terminal window, and auto-launches TightVNC Viewer once the port is up — retries a few times if the viewer window doesn't render. Computes the project root from its own script location, so it works regardless of the caller's cwd (that cwd mismatch caused a real Docker mount error earlier). |
| `docker/run-crawl.ps1` | Host-side script for the actual automated crawl. Reads `url`/`source_type` for a given `name` straight out of `whitelist.yaml` (regex-based mini-parser, not a full YAML parser — matches `whitelist.example.yaml`'s shape only) so there's no copy-paste-into-`-e TARGET_URL=...` step to typo. |

Both `.ps1` files must stay saved as **UTF-8 with BOM** — Windows PowerShell 5.1
mis-renders Korean text in `Write-Host` without a BOM (cosmetic only, but confusing).
If you edit them, re-save with a BOM (`Get-Content -Raw -Encoding UTF8 | Set-Content
-Encoding utf8`) rather than a plain text write.

## The real-target run so far: what happened, what's next

Approved target: `darkforums.ru` (clearnet) / its `.onion` mirror, a MyBB-based forum
with a heavily customized "Knox" theme (not open source, no public template repo
found). `platform: darkforums` is set in the (local, gitignored) `whitelist.yaml`.

**What we already derived from a real snapshot of the homepage** (extracted via
`docker cp`/volume mount, inspected locally, never fetched by Claude directly) and
registered in `site_profiles.PROFILES["darkforums"]`:
- `nav_link_selector: ".forums__forum-name"` — the real subforum list. The generic
  `nav a, .forumbit a` selector had been picking up account-menu items ("Sign Out",
  "Control Panel", etc.) mixed in with real categories; this selector is a
  completely different, clean part of the DOM.
- `rules_link_selector: ".sidenav__menu a"` — separate from `nav_link_selector`
  because on this site the "Rules & Policies" link and the real category list live
  in different DOM subtrees. (This is why `structure.py` now has two independent
  selectors instead of one — a real architecture fix, not just a swapped value.)
- `rules_content_selector: "#content"` — narrows the rules-page text capture to the
  main content area instead of the whole `<body>` (which was pulling in header/
  sidebar/PM-notification noise).
- `stats_area_selector: ".index-stats__forum"` — the sitewide "Total Posts / Total
  Threads / Total Members / Newest Member / Most Online" block. This answers "규모"
  (scale) directly; per-subforum counts (`.forums__stats-count`) exist too but were
  deliberately *not* used for this field since they're per-board, not sitewide.
- `latest_post_timestamp_selector: ".forums__last-post span[title]"` — each subforum
  row's last-post cell shows a relative time ("2 hours ago") but the `title`
  attribute holds an absolute one ("19-08-26, 08:29 PM"). `stats.py`'s timestamp
  logic was generalized to try `datetime` attr → `title` attr → visible text, in
  that order, specifically so relative-time-only display doesn't leak into "최근
  게시일" (CLAUDE.md §7.1 forbids relative time values).

**What's still missing**: an actual thread-list page snapshot. The homepage only
lists subforums, not individual threads, so `content_sample.py`'s
`post_row_selector`/`post_title_selector`/`post_author_selector`/`post_date_selector`
and `stats.py`'s `pagination_last_selector` are still the generic guesses and will
still fail on this site.

## Known traps worth not re-discovering

- **`.gitignore` inline comments don't work.** Git only treats a `#` as a comment
  when it's the very first character of the line. A pattern like
  `whitelist.yaml   # some comment` is parsed as one literal (non-matching) pattern
  string, not `whitelist.yaml` with a trailing comment. This exact bug existed in
  this repo's `.gitignore` for the `whitelist.yaml` rule — it never actually
  ignored the file (confirmed via `git log --all --full-history -- whitelist.yaml`,
  never committed/pushed, but it was a live landmine). Fixed 2026-08-23: comments
  now go on their own line above the pattern. If you add new ignore rules, keep
  comments on separate lines.
- **Windows Docker Desktop + host port 5900**: if a VNC *server* (not just viewer)
  ends up installed and running as a Windows service on the host (this happened once
  via a `winget install` that pulled in TightVNC's server component alongside the
  viewer), it silently binds `0.0.0.0:5900` and blocks Docker's port mapping with a
  cryptic "access forbidden" error — and is itself a minor security exposure (an
  unintended VNC server listening on all interfaces). `vnc-login.ps1` sidesteps the
  conflict by always asking Docker for a random free host port rather than assuming
  5900 is available.
- **`PowerShell` background job + multi-line backtick commands** are fragile to
  copy-paste (trailing whitespace after a backtick silently breaks continuation,
  producing confusing downstream errors like `docker: invalid reference format`).
  Both `.ps1` scripts avoid this by building the whole `docker run` invocation as one
  string internally.
- **Tor takes longer than 3 seconds to bootstrap.** The original `Dockerfile` CMD did
  `service tor start && sleep 3 && python investigate.py ...`; the first crawl in a
  fresh container would frequently time out because Tor's SOCKS proxy wasn't actually
  routing yet. Fixed via `docker/wait-for-tor.sh` (polls up to 60s).
- **`.onion` navigation is slow and sometimes just fails.** `login_session.py` no
  longer crashes on a `page.goto()` timeout — it logs a warning and still lets the
  human retry manually inside the VNC session, then proceeds to the save-session
  step regardless.
